## Context

Voir `proposal.md`. Le socle fournit `apt_add_repo` (deb822, clé `.asc` ou `.gpg`), `apt_install` (paquets manquants seulement), `pkg_installed`, `run`/`run_sudo`/`ui_spin`, `ui_choose`/`ui_choose_multi`, `has_gui`. Le runner exécute `module_install` puis `module_configure` dans **deux sous-shells distincts** (`module_call`) : les réponses données dans `module_install` ne sont pas visibles de `module_configure`, et il n'y a pas de fichier d'état. `module_check` tourne à chaque `--list` et à l'ouverture du menu (rapide, sans réseau).

Vérifié le 21 sept 2026 : le fichier `brave-browser.sources` publié par Brave (suite `stable`, composant `main`, `amd64 arm64`, clé binaire) ; dépôt Mozilla `packages.mozilla.org/apt` (suite `mozilla`, `firefox` 154/155, clé armurée) ; clé Google armurée ; extension 1Password `aeblfdkhhhdcdjpifhhbdiojplfjncoa` (Chrome Web Store) et `{d634138d-c276-4fc8-924b-40a0ea21d284}` (AMO, `1password-x-password-manager`). Ubuntu Desktop 26.04 livre Firefox en snap via le paquet de transition `firefox` `1:1snap1-0ubuntu…` (dans `dpkg`, donc `pkg_installed firefox` est vrai avant même le `.deb` de Mozilla). Brave Sync : aucune stratégie, CLI ni fichier pour rejoindre une chaîne ; le code de 25 mots = graine de 24 mots + un 25ᵉ mot dérivé de la date (`brave-core/components/brave_sync/time_limited_words.cc` : jours depuis le 10 mai 2022 00:00 UTC, arrondis, modulo 2048, liste BIP39 anglaise ; accepté si l'écart est ≤ 1 jour). Sur Linux, Brave et Chrome n'ont pas de réglage de langue d'interface (ils suivent `LANGUAGE`/`LANG`).

## Goals / Non-Goals

**Goals :** un seul module pour les trois navigateurs, sans état, où chaque fonction se déduit de ce qui est installé ; fichiers système écrits de façon idempotente et versionnés ; testable hors ligne (doublures `dpkg-query`, `snap`, `xdg-settings`, `gum`, `sudo`, `curl`, `apt-get`) ; procédures des éditeurs suivies à la lettre (seul le format deb822 change).

**Non-Goals :** gérer la connexion de l'extension à l'app 1Password (elle se fait au premier clic dans l'extension, via la messagerie native que le paquet `1password` installe pour Chrome, Brave et Firefox) ; réglages internes des navigateurs ; langue d'interface de Brave/Chrome (un `.desktop` surchargé avec `env LANGUAGE=…` serait possible, refusé le 21 sept 2026) ; choix des données synchronisées par Brave ; mise à jour du choix de navigateur par défaut hors module.

## Decisions

### D1. Table des navigateurs et deux fonctions dérivées de l'état
Chaque navigateur est décrit par des constantes en tête de module (identifiant, libellé du menu, paquet, fichier `.desktop`, dépôt, clé, dossier de stratégie). `module_install` : questions → dépôts → paquets → snap → navigateur par défaut. `module_configure` : pour chaque navigateur **installé** (`pkg_installed`, pas le choix de l'utilisateur), stratégie 1Password ; préférence de langue Firefox déduite de `pkg_installed firefox-l10n-fr` ; Brave Sync guidé si Brave est installé sans chaîne (D9). Ainsi `module_configure` ne dépend d'aucune réponse, reste idempotent et couvre aussi un navigateur installé à la main.
Alternative rejetée : transmettre les réponses par un fichier temporaire — un état de plus, contraire au principe « `module_check` seule source de vérité ».

### D2. Le navigateur par défaut est réglé à la fin de `module_install`
C'est une configuration, mais le choix n'est connu que dans `module_install` (D1) : la question est posée au début (contrat), l'application (`xdg-settings set default-web-browser <fichier>.desktop`, `xdg-utils` installé par `base` ou ici) se fait dès que les paquets sont là, dans la même fonction. Question posée seulement si le défaut courant (`xdg-settings get default-web-browser`) n'est pas parmi les navigateurs choisis ; un seul choisi → réglé sans question.
Alternative rejetée : `gio mime x-scheme-handler/https` — `xdg-settings` fait la même chose (et plus : `text/html`, `http`, `https`, `about`) selon la doc freedesktop.

### D3. Firefox : dépôt Mozilla, épinglage, `apt_install_pinned`, snap retiré ensuite
Procédure Mozilla : clé `packages.mozilla.org/apt/repo-signing-key.gpg` (armurée → `.asc`), `deb … https://packages.mozilla.org/apt mozilla main`, `/etc/apt/preferences.d/mozilla` (`Package: *`, `Pin: origin packages.mozilla.org`, `Pin-Priority: 1000` — ≥ 1000 autorise le **déclassement**, nécessaire car `1:1snap1` a une époque supérieure à `154.0…`). Comme `pkg_installed firefox` est vrai avec le paquet de transition, `apt_install` ne ferait rien : nouveau helper `apt_install_pinned <paquet...>` dans `lib/apt.sh` = `apt-get install` inconditionnel (même spinner, même `DEBIAN_FRONTEND`), qui installe ou bascule sur la version que la politique apt sélectionne. Le module l'utilise quand `dpkg-query -W -f='${Version}' firefox` contient `snap` ou que le paquet manque ; sinon `apt_install` suffit. Après coup, `snap list firefox` vrai → `run_sudo snap remove firefox` (spinner ; `~/snap/firefox` conservé). Langue (trois options, décision du 21 sept 2026) : « Comme Ubuntu (<code>) » où `<code>` = `${LANG%%_*}` (`fr_CA.UTF-8` → `fr` ; `C`/vide → `en`), « Français », « Anglais ». Résolution → `fr` : `apt_install firefox-l10n-fr` (même dépôt ; Mozilla ne publie pas de `fr-CA`) ; `en` : `apt_remove firefox-l10n-fr` s'il est là (nouveau helper `apt_remove <paquet...>`, paquets présents seulement, même forme qu'`apt_install`) ; autre langue : `log_warn` « pas de paquet de langue prévu », Firefox reste en anglais. `module_configure` déduit la préférence du paquet installé (D5), sans état.
Alternative rejetée : laisser coexister snap et `.deb` (deux Firefox dans le menu, snap par défaut pour les liens).

### D4. Chrome : dépôt deb822 + `/etc/default/google-chrome`
La doc de Google propose le `.deb` (`dl.google.com/linux/direct/google-chrome-stable_current_amd64.deb`), dont le `postinst` crée `/etc/apt/sources.list.d/google-chrome.list` et pose la clé lui-même. Pour rester sur le format deb822 du socle : `apt_add_repo google-chrome https://dl.google.com/linux/linux_signing_key.pub https://dl.google.com/linux/chrome/deb/ stable main amd64` puis `apt_install google-chrome-stable`, précédé de `install_system_file config/navigateur/google-chrome.default /etc/default/google-chrome` (`repo_add_once="false"`, `repo_reenable_on_distupgrade="false"`) : la doc « Linux Software Repositories » de Google documente ces clés pour empêcher le paquet d'ajouter son dépôt. Le comportement du `postinst` face à un `.sources` existant sera constaté en VM (tâche 3.2) : s'il crée quand même `google-chrome.list`, le module le supprime après l'installation (doublon du même dépôt).
`arm64` : Google ne publie pas Chrome pour cette architecture ; option cachée si `dpkg --print-architecture` ≠ `amd64`.

### D5. Stratégies d'entreprise pour l'extension 1Password
Chromium (Chrome `/etc/opt/chrome/policies/managed/`, Brave `/etc/brave/policies/managed/`) : `ExtensionSettings` → `{"aeblfdkhhhdcdjpifhhbdiojplfjncoa": {"installation_mode": "normal_installed", "update_url": "https://clients2.google.com/service/update2/crx"}}` — un fichier `1password.json` versionné (`config/navigateur/chromium-1password.json`), le même pour les deux. Firefox (`.deb` de Mozilla) : `/etc/firefox/policies/policies.json` avec `ExtensionSettings` → `{"{d634138d-c276-4fc8-924b-40a0ea21d284}": {"installation_mode": "normal_installed", "install_url": "https://addons.mozilla.org/firefox/downloads/latest/1password-x-password-manager/latest.xpi"}}` ; en français, `Preferences.intl.locale.requested = {"Value": "fr", "Status": "user"}` (`intl.` fait partie des préfixes autorisés par la stratégie `Preferences`). **Constaté en VM le 21 sept 2026** : avec `Status: default`, Firefox reste en anglais — la valeur par défaut posée par le moteur de stratégies arrive après l'initialisation du service de locale ; `Status: user` écrit la valeur dans `prefs.js`, lue tôt au démarrage suivant. Vérifié ensuite sur un profil neuf : français **dès le premier lancement**. La stratégie ré-applique `fr` à chaque lancement, donc le retour durable à l'anglais passe par le module (« Anglais » retire le paquet et la préférence). Le fichier versionné `config/navigateur/firefox-policies.json` est la base ; la préférence est ajoutée par `jq` dans un fichier temporaire quand `firefox-l10n-fr` est installé, puis `install_system_file`.
Épinglage à la barre d'outils (demande du 21 sept 2026) : `toolbar_pin: force_pinned` (Chromium) et `default_area: navbar` (Firefox) dans la même entrée `ExtensionSettings`. `normal_installed` plutôt que `force_installed` : l'utilisateur garde la main (désactivation, retrait) ; l'extension revient au redémarrage si retirée. Les fichiers dans `/etc` sont des **copies** (pas des liens vers `~/dotfiles` : les navigateurs lisent ces dossiers en 0755 appartenant à root, et un lien vers le home d'un utilisateur serait ignoré par Chromium — les stratégies doivent appartenir à root).
Connexion extension ↔ app : hors périmètre (Non-Goals) ; sur le laptop, l'app installée par `1password` fournit les manifestes de messagerie native ; premier clic sur l'extension → déverrouillage par l'app.

### D6. `install_system_file <rel> <cible> [mode]` dans `lib/files.sh`
Copie `config/<rel>` (ou un fichier temporaire absolu) vers `<cible>` avec `run_sudo install -m <mode> -D` (dossiers parents créés), seulement si `cmp -s` diffère ; comme `link_config`, la fonction journalise elle-même (« Écrit » / « Déjà à jour ») et renvoie 0 dans les deux cas, 1 avec message si la source manque ou si `install` échoue — les tests constatent l'absence de réécriture par l'absence d'`install` dans le journal. Reprend le motif déjà écrit à la main dans `10-1password.sh` (`_op_install_debsig_policy`), qui n'est **pas** refactorisé ici (module archivé et validé ; à faire à l'occasion). Testé dans `tests/test-files.sh` avec `fake_sudo`.

### D7. `module_check`
Toujours 1 (choix interne, décision confirmée le 21 sept 2026) — commentaire explicite dans le module. Le menu le propose donc coché à chaque relance ; `Entrée` repose la question, précochée avec les navigateurs installés, et rien n'est réinstallé.

### D8. Tests (`tests/test-navigateur.sh`)
Doublures : `dpkg-query` (liste + versions : `firefox` en `1:1snap1` ou `154.0`), `snap` (`list`/`remove` sur un marqueur), `xdg-settings` (`get`/`set` sur un fichier), `gum` (réponses scriptées par variables : `choose --no-limit` → navigateurs, `choose` → langue, défaut, menu sync), `sudo` (`fake_sudo`), `apt-get` (journalise, marque le paquet installé ou retiré), `curl` (clés factices), `op` (graine factice de 24 mots, compte les lectures), `wl-copy` (écrit dans un fichier ; `--clear` le vide), `brave-browser` (journalise l'URL), `install`/`cmp`/`jq` réels ; `APT_KEYRINGS_DIR`, `APT_SOURCES_DIR`, `APT_PREFERENCES_DIR`, `NAV_ETC` (préfixe de `/etc`), `NAV_BRAVE_PREFS` (fichier `Preferences`), `NAV_NOW` (date du calcul) et `LANG` redirigés dans `$TEST_TMP`. Cas : questions dans l'ordre (navigateurs, langue, défaut) avant tout `apt-get` ; sélection vide ; Brave seul → dépôt + paquet + défaut sans question + stratégie Brave seule ; Firefox avec paquet de transition → `apt_install_pinned`, épinglage, snap retiré après ; Firefox non choisi → snap intact ; Chrome → `/etc/default/google-chrome` avant `apt-get` ; langue : « Comme Ubuntu » avec `LANG=fr_CA.UTF-8` → `l10n-fr` + préférence, avec `en_CA` → rien, « Anglais » avec `l10n-fr` présent → `apt_remove` et préférence retirée ; réexécution → aucune écriture (`install` non appelé) ; Brave Sync : 25ᵉ mot sur deux dates connues (dont le passage de minuit UTC), phrase de 25 mots dans le presse-papiers et jamais dans le journal, `brave-browser` ouvert sur la page de sync, chaîne détectée → presse-papiers vidé, « Passer » → étape manuelle, sans session `op` → avertissement + étape manuelle + code 0, chaîne déjà rejointe → aucune lecture `op` ; `module_check` = 1.

### D9. Brave Sync guidé (étape interactive dans `module_configure`)
Précédent : `_op_connect_via_app` du module `1password` (ouverture de l'app, consigne, attente d'un signal sur disque, menu de reprise). Déroulé, si `pkg_installed brave-browser` et pas de chaîne (`jq -e '.brave_sync_v2.seed // empty'` sur `~/.config/BraveSoftware/Brave-Browser/Default/Preferences` — clé à confirmer en VM) : 1) `seed=$(op_read "$NAV_BRAVE_SYNC_REF")` (`op://Imarcom/Brave Sync Code/notesPlain`, note sécurisée dans le coffre `Imarcom` : le coffre est nommé dans la constante, la convention de CLAUDE.md est assouplie en conséquence ; les 24 premiers mots retenus, séparés par espaces ou retours à la ligne, ce qui accepte un code de 25 mots périmé enregistré tel quel) — échec (pas de session, item absent) → `log_warn` + `manual_step`, retour 0 ; 2) `word25=$(_nav_brave_word25)` : `days=$(( (now - epoch_20220510 + 43200) / 86400 ))` en UTC (arrondi au plus proche comme `std::round`), `sed -n "$((days % 2048 + 1))p" config/navigateur/bip39-english.txt` (liste officielle BIP-0039, 2048 mots, versionnée) ; 3) `printf '%s %s' "$seed" "$word25" | wl-copy` (`wl-clipboard` installé par `apt_install` ; pas `run` : rien au journal) ; 4) `setsid -f brave-browser --no-first-run` (détaché, sorties `/dev/null` comme `_op_open_settings`), après création du fichier sentinelle `~/.config/BraveSoftware/Brave-Browser/First Run` ; consigne : « barre d'adresse `brave://settings/braveSync/setup`, coller le code (Ctrl-V) dans “I have a sync code”, puis choisir les données à synchroniser » — **constaté en VM le 21 sept 2026** : Chromium ignore les URL `brave://` reçues en ligne de commande, au démarrage comme vers une instance en marche (nouvel onglet vide), et `--no-first-run` seul ne supprime pas l'assistant de bienvenue de Brave (il revient à la navigation suivante) alors que la sentinelle « First Run » (mécanisme Chromium) le supprime ; 5) `ui_wait` 300 s / 2 s sur la présence de la chaîne, puis menu « Continuer d'attendre / Passer » ; rejoint → `wl-copy --clear`, `log_ok` ; passé → `manual_step "Brave Sync : rejoindre la chaîne (brave://settings/braveSync)"`. Le calcul du 25ᵉ mot est une fonction pure testée sur des dates fixes (`NAV_NOW` surchargeable). **Vérifié le 21 sept 2026** sur la note réelle (25 mots ; code copié le matin même) : le 25ᵉ mot enregistré correspond à l'index 1596 = `round(1595,75)`, soit « 2026-09-22 » — l'arrondi de Brave fait basculer le mot à **12:00 UTC** (8 h au Québec), pas à minuit ; le module reproduit cet arrondi.
Alternatives rejetées : copier le code de 1Password tel quel (refusé par Brave dès le surlendemain) ; demander un code frais sur le téléphone (étape manuelle sans valeur ajoutée du script) ; éditer `Preferences` (entrées protégées par HMAC, remises à zéro).

## Risks / Trade-offs

- [Le `postinst` de Chrome crée `google-chrome.list` malgré `repo_add_once=false`] → constaté en VM ; suppression du `.list` par le module en secours (le `.sources` couvre le même dépôt).
- [Déclassement `1:1snap1` → `154.0` refusé par `apt-get`] → priorité 1000 (autorise le déclassement selon `apt_preferences(5)`) ; **constaté en VM le 21 sept 2026** : apt sélectionne bien la version de Mozilla mais `-y` exige `--allow-downgrades` (« Packages were downgraded and -y was used without --allow-downgrades ») → ajouté dans `apt_install_pinned`.
- [`snap remove firefox` lent ou bloqué par un Firefox ouvert] → exécuté sous spinner, après le `.deb` ; échec → module en échec avec l'extrait du journal, relance possible.
- [Stratégie « managed » affichée comme « géré par votre organisation » dans le navigateur] → assumé : c'est le mécanisme officiel de pré-installation ; `normal_installed` laisse l'utilisateur désactiver l'extension.
- [Extension installée mais pas connectée à l'app] → premier usage : l'extension demande à déverrouiller via l'app (messagerie native fournie par le paquet `1password`) ; sans app, connexion classique dans l'extension.
- [Défaut de navigateur ignoré par GNOME] → `xdg-settings` écrit `~/.config/mimeapps.list` ; vérifié par `xdg-settings get` et un `xdg-open https://…` en VM.
- [Chrome indisponible sur `arm64`] → option masquée ; la VM et le laptop sont `amd64`.
- [Le calcul du 25ᵉ mot diverge de Brave (arrondi, fuseau)] → date en UTC, arrondi comme `std::round`, test unitaire contre des dates connues et vérification en VM contre le code affiché par un autre appareil ; fenêtre de ±1 jour tolérante.
- [La phrase de 25 mots passe par le presse-papiers] → assumé (c'est ce que l'utilisateur ferait à la main) ; vidé dès la chaîne rejointe (`wl-copy --clear`) ; jamais affichée ni journalisée ; sur GNOME neuf, aucun gestionnaire d'historique du presse-papiers.
- [La clé de `Preferences` qui signale la chaîne est mal identifiée] → `brave_sync_v2.seed`, **confirmée en VM le 21 sept 2026** (absente avant, chaîne (`seed`, `reset_devices_progress_token_time`) écrite ~1 s après la confirmation dans Brave) ; le délai d'attente et le menu « Passer » évitent tout blocage.
- [L'assistant de bienvenue de Brave masque la page de sync au premier lancement] → constaté en VM : sentinelle « First Run » + `--no-first-run` ; la page de sync est atteinte par l'utilisateur (URL tapée ou menu), décision du 21 sept 2026 après trois essais de lien profond infructueux.
- [Brave met plusieurs secondes à écrire `Preferences`] → sondage toutes les 2 s pendant 300 s, comme le module `1password`.
